# game-jam: acceptance scenarios

1. The submitted build completes the core loop within the actual jam rules. Record the fixture, action, expected result and observed result.
2. A clean download, missing network and the final upload window are checked. Record the fixture, action, expected result and observed result.
3. Scope cuts protect a playable submission and asset rights follow the jam policy. Record the fixture, action, expected result and observed result.

Run the smallest relevant scenario in the real engine/browser, then the neighboring lifecycle path.
For an existing project, compare before/after using the same fixture. A document validator or mocked API does not verify the engine behavior. Mark unavailable runtimes as untested; include the command or manual steps another developer can run.
