# fps-shooter: acceptance scenarios

1. Look, fire, hit confirmation, reload, enemy response and restart form a complete loop. Record the fixture, action, expected result and observed result.
2. Zero ammo, simultaneous death and lost pointer lock have usable recovery. Record the fixture, action, expected result and observed result.
3. Visual recoil does not silently change the authoritative shot unless designed. Record the fixture, action, expected result and observed result.

Run the smallest relevant scenario in the real engine/browser, then the neighboring lifecycle path.
For an existing project, compare before/after using the same fixture. A document validator or mocked API does not verify the engine behavior. Mark unavailable runtimes as untested; include the command or manual steps another developer can run.
